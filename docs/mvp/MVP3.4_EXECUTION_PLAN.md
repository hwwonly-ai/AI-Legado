
# MVP 3.4 书籍级角色管理执行计划

## 1. 目标

在书籍维度维护可持久化的角色档案，为后续 AI 角色识别、角色匹配和跨章节音色复用提供稳定的数据基础。

本阶段只实现角色配置与手动维护，不接入 AI 自动识别，不改变当前规则分段仅区分 `narrator` / `dialog` 的行为。

## 2. 实施范围

- 新增、编辑、删除书籍角色。
- 维护角色名、别名、备注、锁定状态。
- 为角色按当前 HTTP_TTS 引擎绑定音色，可跟随书籍旁白/对白音色或手动输入音色 ID。
- 未单独绑定音色时，回退 MVP 3.3 的书籍级默认对白音色。
- 角色配置随书籍保存，重新打开书籍后仍可读取。
- 从朗读引擎设置页进入当前书籍的角色管理页面。

## 3. 非目标

- 不识别正文中的具体说话人。
- 不将规则生成的 `dialog` segment 自动匹配到角色。
- 不调用 AI 服务，不维护 AI Prompt。
- 不新增角色或 segment 的 Room 表。
- 不修改豆包、阿里云账号和全局 HTTP_TTS 登录配置。
- 不提前实现角色合并、拆分、导入导出和跨书共享。

## 4. 技术方案

### 4.1 数据模型

新增通用角色模型 `BookReadAloudRole`，建议字段：

```kotlin
@Parcelize
data class BookReadAloudRole(
    val id: String,
    var name: String,
    var aliases: MutableList<String> = mutableListOf(),
    var note: String = "",
    var voices: HashMap<String, String> = hashMapOf(),
    var locked: Boolean = false
) : Parcelable
```

字段约束：

- `id`：创建时生成 UUID，角色改名后仍保持稳定。
- `name`：必填；同一本书内忽略首尾空格后不可重复。
- `aliases`：去除空白项和重复项；不可与其他角色名或别名冲突。
- `note`：可选，仅用于人工记录，不参与 MVP 3.4 匹配。
- `voices`：key 为 TTS 引擎标识，value 为自定义 voice / speaker ID，或跟随书籍旁白/对白音色的内部标记。
- `locked`：标记用户确认的角色，供后续 AI 阶段避免自动覆盖。

### 4.2 持久化

在 `Book.ReadConfig` 中新增角色列表字段，例如：

```kotlin
var readAloudRoles: MutableList<BookReadAloudRole> = mutableListOf()
```

继续使用现有 `Book.ReadConfig` JSON TypeConverter 和 `book.save()` 保存，不新增数据库表和 Room migration。

在 `Book` 上提供最小操作接口：

- 获取角色列表。
- 按 ID 新增或更新角色。
- 按 ID 删除角色。
- 获取角色在指定 TTS 引擎下的音色。
- 清理和校验角色名、别名、音色输入。

所有集合读取需兼容旧书籍 JSON 中字段缺失或为 `null` 的情况。

### 4.3 音色回退规则

角色的最终音色按以下顺序确定：

1. 角色在当前 TTS 引擎下绑定的音色。
2. MVP 3.3 当前书籍的默认对白音色。
3. 当前 HTTP_TTS `loginInfo` 中的全局对白音色。
4. Provider 原有默认音色。

角色选择跟随书籍旁白/对白音色时保存跟随标记，读取时动态解析当前书籍音色，避免书籍音色修改后角色仍使用旧值。

MVP 3.4 先实现和展示该规则，不把角色音色接入现有规则 `dialog` segment；具体人物 segment 的消费留到后续角色匹配阶段。

## 5. UI 方案

### 5.1 入口

在 `SpeakEngineDialog` 的书籍设置区域增加“书籍角色”入口，与现有“书籍音色”并列。

入口仅在存在当前书籍时可用。系统 TTS 或不支持分角色音色的 HTTP_TTS 下仍允许维护角色基础信息，但音色输入禁用并显示说明。

### 5.2 角色列表页

新增书籍角色管理 Dialog，包含：

- 顶部标题和新增按钮。
- 角色列表：角色名、别名摘要、当前引擎音色、锁定状态。
- 点击条目进入编辑。
- 删除操作需要二次确认。
- 空列表显示引导文案。

列表使用项目现有 RecyclerView / Adapter 风格，不引入新 UI 框架。

### 5.3 新增/编辑页

表单字段：

- 角色名，必填。
- 别名，使用换行或逗号分隔输入，保存时统一解析。
- 当前引擎音色，可为空。
- 备注，可为空。
- 锁定开关。

保存前完成格式化和冲突校验，错误直接显示在对应输入框，不写入不完整数据。

## 6. 实施步骤

### 阶段 A：模型与持久化

1. 新增 `BookReadAloudRole` 数据类。
2. 扩展 `Book.ReadConfig` 保存角色列表。
3. 增加 `Book` 角色读写、音色读取和空值兼容方法。
4. 增加角色名、别名规范化与冲突校验。

完成标准：构造书籍角色后执行现有 JSON 序列化/反序列化，字段和值保持一致。

### 阶段 B：角色列表

1. 新增角色管理 Dialog、列表布局和条目布局。
2. 实现空状态、角色摘要和锁定状态展示。
3. 实现新增、编辑、删除入口及删除确认。
4. 在 `SpeakEngineDialog` 增加“书籍角色”入口。

完成标准：用户能从当前书籍朗读设置进入列表，并完整执行增删改流程。

### 阶段 C：角色编辑与音色绑定

1. 新增角色编辑 Dialog 和输入校验。
2. 根据当前 HTTP_TTS 判断 Provider 和音色字段提示。
3. 按 TTS 引擎保存角色音色，切换引擎时互不覆盖。
4. 展示角色音色为空时的书籍默认对白音色回退信息。

完成标准：同一角色可分别保存阿里云 voice 和豆包 speaker，切换引擎后显示对应值。

### 阶段 D：资源与兼容性收尾

1. 补充默认英文和简体中文字符串资源。
2. 检查深色主题、长文本、空别名和无当前书籍场景。
3. 确认旧书籍配置读取正常，不影响 MVP 3.3 音色设置。
4. 更新 `MVP PLAN.md` 的 3.4 实现记录与状态。

## 8. 验收用例

1. 为书籍新增角色“张三”，填写别名、备注并锁定，重新打开后数据仍存在。
2. 同一本书不能新增另一个名为“张三”的角色。
3. 其他角色不能使用已存在的角色名或别名作为自己的名称或别名。
4. 为“张三”绑定豆包 speaker，切到阿里云后可独立绑定 voice，两个值互不覆盖。
5. 清空角色音色后，界面提示将使用书籍默认对白音色。
6. 编辑角色名不会改变角色 ID，也不会丢失已有音色映射。
7. 删除角色需确认，删除后重新打开书籍不再出现。
8. 不支持分角色音色的 TTS 下仍可编辑角色资料，但不能写入无效音色。
9. 没有角色配置的旧书籍可正常打开和朗读。
10. MVP 3.3 的旁白和默认对白音色配置保持原行为。

## 10. 风险控制

- 角色名和别名冲突会影响后续自动匹配，因此 MVP 3.4 必须在写入时统一校验。
- 音色必须按 TTS 引擎隔离保存，避免豆包 speaker 被错误用于阿里云 voice。
- 不在本阶段把角色强行接入规则对白，否则在没有具体人物识别时会产生错误角色分配。
- 使用书籍 JSON 配置可降低当前改动成本；后续 MVP7 直接复用该角色档案做 AI 角色匹配，不再单独建设角色档案表。
